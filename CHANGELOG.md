# Changelog

Notable changes to `tare.tools.kernel` are recorded here, newest first.

## Unreleased

- AGY: a catalog action the model called as a function is repaired once instead of ending the session. Claude Sonnet 5.5 on AGY 1.5.9 calls `verify`, `search` or `tare_deliver` as functions although the request tells it they are data; the agent has only `finish`, so AGY answers "unknown tool", fires no tool hook, runs nothing and reports SUCCESS with an empty reply. `decode_agy` raised a final `CLI_UNEXPECTED_TOOL` and the session blocked (3 of 4 real implementer sessions on 2026-11-14, one of them after the edit and the check had passed). When every stray tool step ended in AGY's own "unknown tool" error and no tool hook fired, the failure is now retryable and names the mistake, so the existing one-time repair resends the request with that note; the rejected attempt's usage stays in the receipt. A tool that ran, a tool Tare's hook saw, or any other tool error is refused as before. With the change 6 of 6 real sessions delivered (8 of 26 model calls were repaired); Claude Opus 5.5 and Gemini 4 Hydrogen on AGY delivered with no repair.
- `claude_models`: an alias whose CLI start fails (a timeout, a refused launch) is that alias unresolved (None) and the remaining aliases are still read; before, one failure lost the whole reading. The guidance tests post to the loopback recorder without the host's proxy settings, so a proxy configured on the machine can neither receive their fixture request nor fail them. Both found by an independent review of this change by a model of another vendor.
- `vendor_guidance.claude_models(executable, aliases)` says which model id the installed Claude Code resolves each family alias to, with zero tokens: `{'cli_version', 'models': {alias: model id or None}}`. Each alias is one start of tare's command against the zero-token reading's recorder on 127.0.0.1, which refuses the request; only its `model` field is kept, never the rest of the body or a header. The caller passes the aliases. Claude Code sends an alias it does not know unchanged, so a model that is not `claude-<alias>-<version>` comes back as None, as does a start that sends nothing; a CLI older than 2.1.322 raises the reading's `ValueError`. Measured on 2026-11-14 with Claude Code 2.1.325 on Windows: `fable` -> `claude-fable-5-2`, `opus` -> `claude-opus-5-5`, `sonnet` -> `claude-sonnet-5-5`, `haiku` -> `claude-haiku-5-5`, `mythos` and `zzz` -> None, about 6 s for four aliases. The guidance reading and the alias reading share one recorder; the reading's items are unchanged. `tools/vendor_guidance_capture.py models` runs it by hand. Version 0.9.90.
- CI: the Linux sandbox job keeps the two narrow allowances and no longer lifts the AppArmor restriction for every program. Measured on stock Ubuntu 24.04.5 on 2026-11-13: all three let the real-sandbox tests pass (28 of 28), and with either profile `kernel.apparmor_restrict_unprivileged_userns` stays 1. Each run now records whether another program still gets no capabilities in a user namespace (`unshare -Urn ip link set lo up`); the earlier `unshare -U true` only showed that a namespace can be created, which the restriction allows.
- CI: the `Linux sandbox (bubblewrap)` job now runs three times on stock Ubuntu 24.04, once per way of allowing bubblewrap its user namespace: an AppArmor profile for `/usr/bin/bwrap` alone that only grants `userns`, Ubuntu's own `bwrap-userns-restrict` profile (package `apparmor-profiles`), and the restriction lifted for every program (`kernel.apparmor_restrict_unprivileged_userns=0`, what the job did until now). Each run records whether another program is still refused a user namespace and then runs the real-sandbox tests, so the narrow allowance tare recommends to a user is the one CI proves.
- Linux sandbox for checks (`compute_plane/linux_bwrap.py`, standard library only), the counterpart of `windows_mxc`: `BwrapPolicy(read_only, read_write, denied)`, `policy_sha256`, `require_support()` and `LinuxBwrapProfile`, a `process_factory` for `run_process` whose receipts carry backend `linux-bwrap`. bubblewrap shows only the policy's paths, read-only or writable, masks every denied path that exists at launch (mode 000, read-only), gives the sandbox its own user, PID, IPC and network namespaces (a private loopback), no capabilities, no nested user namespaces, 1024 tasks and no core dumps, and loads a seccomp filter that refuses sockets other than AF_UNIX, AF_INET, AF_INET6 and AF_NETLINK, `io_uring` and foreign-architecture syscalls (an AF_VSOCK socket was created inside `bwrap --unshare-net` on WSL2; with the filter it is EPERM). Each launch refuses a scope whose real path changed or a denied path that moved since the profile was made. `require_support()` names why a host has no sandbox (`bwrap_missing`, `bwrap_too_old` before 0.8, `bwrap_userns_refused` for stock Ubuntu 24.04's AppArmor restriction, ...) and never falls back to a weaker one. Linux does not match Windows on: no memory cap, a private rather than denied loopback, `/etc` and the names of the folders above granted paths visible, and no sandbox on a host without unprivileged user namespaces. Proved on WSL2 (Ubuntu 24.04, bubblewrap 0.9.0); a new CI job, `Linux sandbox (bubblewrap)`, records a stock GitHub Ubuntu 24.04 runner's state, lowers its AppArmor restriction and runs the real-sandbox tests, where a skip fails. Nothing uses the module yet. Version 0.9.89.
- `read('cli://agy', ...)` returns the installed AGY's version (still no items and no tokens), so the host knows when a real reading of a new AGY version is due.
- Vendor guidance reads what the CLIs really send. Codex's zero-token reading now renders `debug prompt-input` as tare's `exec` call: the installed skills (their `SKILL.md`, `agents/*.yaml` and plugin manifest, copied into an empty `CODEX_HOME`, so neither the login nor `config.toml` is read) under exec's approval policy and read-only sandbox; on 0.166.0 every block equalled Codex's own session record of a real call (skills 16,170 characters, permissions 341), where the empty-home reading had shown 1,938 and 3,882. The removal proof uses the same rendering. New `read_real(endpoint, executable, model=...)`, a separate call because it spends tokens: Claude Code makes one minimal real call with tare's mod in a recording mode (each piece as sent, one file each) and marks what the zero-token reading missed (on 2.1.322, `attachment:total_tokens_reminder`; removing it was checked from the mod's own record); AGY makes one minimal real call and is read from the conversation that call reported (`gen_metadata` in AGY's SQLite store, a protobuf read by its text marks, never by field numbers), giving the frames around tare's system text and request, the `ADDITIONAL_METADATA` and `USER_SETTINGS_CHANGE` blocks and the `finish` and `manage_task` tools, all read-only. `AGY_STARTING_POINT` holds what AGY 1.5.7 showed on 2026-11-12. The AGY and Claude command builders are now `agy_invocation` and `claude_invocation`; unguided calls are unchanged.
- Vendor guidance, Claude: an edited block is sent with the real values in place of the placeholders tare shows (`<date>`, `<OS version>`, `<working directory>`, the model's name, id and knowledge cutoff, `<account email>`); before, the placeholders went out as written. The mod takes each value from the text Claude Code wrote for that same block.
- Vendor guidance reads what each CLI adds instead of shipping a fixed list: `read(endpoint, executable)` starts Claude Code with tare's own command against a recorder on this machine (127.0.0.1) that refuses the first request, so the login token stays inside the machine and nothing reaches the provider (about 2 s), with a reading mod that marks each context block and attachment by name; Codex is read with `debug prompt-input` (under 1 s). Machine and day values become placeholders, so two readings give the same hashes. Ids now follow the block (`context:userEmail`, `attachment:environment`, Codex's leading tag) and their shape decides the controls, so a block a newer CLI adds needs no code. `tools/vendor_guidance_capture.py` is a thin command over the reading.
- Vendor guidance, Claude: a guided call no longer refuses the codecs that run with hooks off (summaries, calls without tools such as heads-up notes, the rollback codecs). It drops `disableAllHooks` instead, keeping `enabledPlugins: {}`, so the mod runs in every shape. That also runs the hooks of Claude Code's built-in plugins (agents-md, telemetry, privacy, plugin-authoring on 2.1.322), as the native codec with tools already does on every call; the receipt says so (`hooks_turned_on`). Measured with zero tokens on 2.1.322 in five shapes: the chosen blocks are absent, the replacement present, and the request otherwise unchanged. Unguided calls are byte-identical, now also pinned for a Claude call without tools.
- Vendor guidance (`compute_plane/vendor_guidance.py`, `docs/VENDOR_GUIDANCE.md`): a catalog of the blocks each vendor CLI adds to tare's requests on its own, measured with zero tokens (Claude Code 2.1.322: account email, environment, model, date, identity line, billing header, tool descriptions; Codex 0.166.0: skills, permissions, collaboration mode, environment context; AGY: not inspectable), the protocol texts tare sends (read-only, derived from `cli_request`), and `VendorCliClient(..., vendor_guidance=...)` to apply the owner's choices. Claude choices travel as a mod loaded with `--plugin-dir` in Claude decisions; summaries and the rollback codecs run with hooks off, so a Claude choice is refused there, as on a Claude older than 2.1.322 or without `--plugin-dir`. Codex removals become `-c` switches, proved once per Codex version with `codex debug prompt-input` (nothing sent) or refused. Every refusal comes before anything is sent (`CLI_GUIDANCE_UNSUPPORTED`). With no choice each CLI receives the same bytes as before, pinned per codec by a test. `tools/vendor_guidance_capture.py` re-measures a new CLI version.
- The verification-deadline test allows float rounding in the remaining time: on a Windows runner whose clock had not ticked, `(now + 1000) - now` came out as 1000.0000000000001 and failed `<= 1000` (run of 2026-11-10, passed on rerun).
- New protocol `gemini-generate-content`: Gemini's own `generateContent` API, which is how OpenCode lists Gemini 4 Argon. Non-streaming; the model's parts are replayed with their thought signatures, tool results go back as `functionResponse` in a turn of their own, the last forced call restricts the choice to `tare_deliver`, and a reply that did not finish with `STOP` has no effects. It takes the `opencode-exclusive` usage contract (`usageMetadata` carries the same `cost` and `opencode` block), the declared session header and `billing_sources`. Qualified live through OpenCode on 2026-11-10 (read, edit, verify, deliver in four calls); Google's own endpoint is not qualified.
- A read page that reaches the end of the file returns `final_newline`, whether the file ends with a line break, which the numbered lines cannot show; the read tool asks the model to keep it unless the task changes it. Claude Haiku 5.5 took `value = 1` for a file without a final newline and replaced it with `value = 2` plus a newline, doubling it, so its verifier failed (OpenCode qualification, 2026-11-09).
- A 429 whose Retry-After outlasts the call's remaining time (a spent plan resets in hours) is no longer retried at once, which only drew more refusals; a short one still is. An error type shaped like a key is dropped like any key in a provider's message.
- A profile may declare `billing_sources`; a reply that OpenCode bills to any other source (`usage.opencode.billing_source`, e.g. `balance` once a subscription allowance is spent with Extra Usage on) keeps its usage, is observed as `billing_refused` and ends the session with `BILLING_SOURCE_REFUSED`, so at most one call is charged that way. A refused HTTP 429 keeps its error type (a single word, such as OpenCode's `GoUsageLimitError` with Retry-After), never its text, so the host can tell a spent plan and its reset from a passing rate limit; observed live on 2026-11-09 after twelve calls spent a 5-hour window.
- The OpenCode gateway contract follows its audit: a cost OpenCode marks `estimated` (the customer's own provider key) is not taken as a charge, and exchange headers are checked before any request header or credential is read. The Responses `prompt_cache_key` is the first 64 characters of the session key the header carries.
- OpenCode gateway contract. A profile may declare `session_header: x-opencode-session`, the only provider session header admitted, on the chat, Responses or Messages protocols. The adapter then sends the session's opaque key, the same one behind OpenRouter's `session_id` and the Responses `prompt_cache_key`, as that header on every generation exchange, streamed or not, so OpenCode can route and cache by conversation. Per-exchange headers outside that list, or with control characters, are refused before dispatch. Profiles without the field keep their digest. New usage contract `opencode-exclusive` for the same three protocols: it reads OpenCode's disjoint `usage.opencode.tokens` and reports `usage.cost` (0 for Go use within its limits) with `billing_source`, `list_cost` and the Go `allowance`, so the OS can meter the Go plan per model.
- A vendor CLI release the adapter has not seen first answers one small probe per model through the same path before the real request (the request with its conversation replaced by one short record, same decoder and repair, at most 60 seconds). A shape failure is recorded and returns CLI_QUALIFICATION_FAILED before the user's request is sent, and later calls fail fast without another probe; a probe cut short is CLI_QUALIFICATION_INTERRUPTED (retryable); quota and provider failures keep their own code and are no verdict. The host can pass a persisted `qualification` mapping so each machine probes a release once per model. AGY updated from 1.2.7 to 1.5.3 on 2026-11-07 and receipts only noted the change until a session blocked.
- A final action the AGY CLI itself rejected is repaired once instead of blocking the session: AGY 1.5.3 marks finish ERROR when the model breaks the schema (a missing 'text', a key written '"\"text"') yet reports SUCCESS with that reply, which tare could not decode (CLI_INVALID_RESPONSE, a blocked TUI session on 2026-11-09). Earlier versions let the model correct it in the same run. The adapter now sends the request again naming the rejection; the response keeps the repair's own usage (for vendor CLIs it is the size measurement of one request), and the first attempt, with its usage, stays in the receipt (`repair_of`), also when the repair is cut. A second rejection is a retryable failure; a reminder that would not fit the request limit reports the rejection.
- The test-tool download waits out an outage of some minutes, not 30 seconds: eight tries with backoff capped at a minute (about three minutes). The first window ran out on this change's own Windows run, eight 504s in 42 seconds.
- The CI test-tool download (ripgrep from GitHub's releases) retries a 5xx, 429, reset or timeout up to five times with backoff: on 2026-11-09 one 504 failed every shard of several runs. A 404 or a digest mismatch still fails at once.
- A read with `start_column: 1` returns a page again, not one line: models fill that default from the schema, and a DeepSeek implementer got a single line per read, repeated the read and was stopped for no progress. Column mode is for continuing a line from a later column or reading a line longer than a page.
- The provider reason drops every request header value a gateway might echo (account and session ids too), not only those named like credentials; Content-Type, Accept, Content-Length and User-Agent are kept.

- A refused HTTP request (4xx other than 429) keeps the provider's reason in its transport receipt as `provider_error` (error type and at most 300 characters of message), after the worker removes every credential header value and anything shaped like a key. Only the status was kept, so an Anthropic HTTP 400 could not be told apart (thinking signature, parameter or size). 429 and 5xx replies still keep only Retry-After and a known busy reason.

- Fix forced final delivery incompatible with Anthropic thinking: the last call keeps automatic tool choice unless the profile explicitly sets `thinking` to an object with `type: disabled`. The budget warning and thinking parameters are preserved; OpenAI protocols still force the delivery tool. Covered by offline payload regressions, not live API validation.

- `restore_bytes` undoes a deletion: with `after=None` it recreates the file's earlier bytes while the file is still absent, and preserves a file created in the meantime. Undoing a turn that deleted a file failed with `invalid_restore_snapshot`.
- Boolean tool arguments accept the text `"true"`/`"false"` that text-only call formats (Qwen's XML form) send, as `"null"` already was for a missing file's hash, so a local model can delete a file; Codex's strict replies carry `delete: null` for an ordinary edit.
- The native `edit` tool deletes a file: `delete=true`, `changes=[]` and the file's current SHA-256, within the writable scope and review, rechecking the hash before the unlink and recording the intent so an interrupted deletion is recovered without replay. A native implementer could create and change files but never remove one, so a file it created by mistake stayed in its candidate. It is the only deletion: the standalone `delete` operation of `mediated_tools`, which no host offered and which lacked those guards, is removed.
- CI runs on GitHub-hosted Linux and Windows runners (`Tests (linux)`, `Tests (windows)`) with the README's own install commands: the runtime and SpecGraph come from their public repositories at the pinned commits, without deploy keys or a hand-made environment. The repository variables `CI_RUNNER_LINUX` and `CI_RUNNER_WINDOWS` move it to your own runners, and pull requests from forks then skip it. The README installs the runtime and SpecGraph at the commits CI pins; the ones it named are not published.
- `test_default_read_returns_on_first_output` keeps its child running for 60 s instead of 1 s: on a loaded runner the read could start after the child had exited.
- CI pins the agent runtime and SpecGraph at the first commits of their public repositories; the commits it pinned before are not published.
- First public release. The repository starts from a single commit; earlier history is not published. It contains the
  kernel described in the README (provider adapters, mediated tools, Git workspaces, terminal sessions, hooks and
  append-only session journals), its specifications and contracts, among them the GPU lease contract, and the test
  suite.
